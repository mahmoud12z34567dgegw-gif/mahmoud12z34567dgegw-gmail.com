# أكاديمية أهل القرآن — إصدار 1.5: غرف صوتية داخل التطبيق

هذا تحديث لمشروع Android السابق، يحذف واجهة «الفصول المرئية» وروابط Google Meet ويضع بدلًا منها «الغرف الصوتية» داخل التطبيق. **لا كاميرا، ولا صور للمشاركين، ولا Google Meet، ولا مشاركة شاشة.** يَظهر كل مشارك باسمه والحرف الأول من اسمه فقط. معلم الأكاديمية ينشئ غرفة، يدعو طلابًا محددين، ويمنح/يلغي حق التسميع؛ الطالب يبدأ مستمعًا وميكروفونه مغلق. هناك كتم شخصي، مغادرة، وإنهاء الحصة بواسطة المعلم.

## ما هو حقيقي وما الذي يحتاج إعدادًا؟
- واجهة Android + عميل LiveKit للصوت + خادم Cloudflare Workers/D1 للمصادقة والغرف وتوليد توكنات المشاركة: **الكود موجود في الحزمة**.
- لتشغيل الصوت بين موبايلات مختلفة يجب أولًا **نشر** مجلد `voice-backend` على حساب Cloudflare وربطه بمشروع LiveKit Cloud، ثم كتابة الرابط العام الناتج `https://...workers.dev` في `app/src/main/assets/voice-config.js` وإعادة بناء APK. هذا العنوان مجاني من Cloudflare؛ لا تحتاج شراء دومين خاص.
- **لا تضع مفاتيح LIVEKIT_API_SECRET ولا كلمة مرور المدير في app/ أو GitHub أو APK.** استخدم Cloudflare Secrets. الحسابات التجريبية `@ahlquran.test` تظل محلية وتخص وظائف النسخة القديمة؛ لحضور الحصص الصوتية بين الأجهزة استخدم **حسابات سحابية منفصلة** ينشئها المدير داخل قسم «الغرف الصوتية» بعد الربط. اسم بريد الدخول ليس إنشاء صندوق بريد حقيقي.
- لم تُجرَ مكالمة فعلية بين جهازين في بيئة العمل هذه، ولم يُختبر النشر الفعلي على حساباتك؛ اختبارات المصدر وواجهة API الأولية فقط. اعتبر المشروع نسخة **اختبار تكامل** إلى أن تختبر إنشاء غرفة والدخول والتسميع والإذن على هاتفَي المعلم والطالب.
- لا تستخدم أسماء أو تسجيلات أطفال حقيقية قبل مراجعة الخصوصية وسياسة الموافقة، ولا تنشر بيانات الدخول في المستودع العام. التطبيق لا يسجّل الصوت على الخادم من تلقاء نفسه.

## البناء على GitHub
1. حمّل الحزمة ZIP وفك الضغط ثم ارفع **محتوياتها** بنفس المسارات إلى مشروع GitHub الحالي، أو أضف مجلد `app` وملفات Gradle و`.github` و`voice-backend` بالموقع الصحيح؛ احتفظ بنسخة من الإصدار القديم قبل الاستبدال.
2. ملف `.github/workflows/build-apk.yml` يستخدم `android-actions/setup-android@v4` وينشر APK تجريبيًا باسم **AhlAlQuran.apk** داخل GitHub Releases عند نجاح البناء.
3. شاشة «الغرف الصوتية» توضح حالة الربط بصدق؛ لا يتم إنشاء اتصال وهمي عندما يكون `voice-config.js` فارغًا.
4. رقم Android versionCode=7؛ قد تختلف شهادة توقيع Debug بين بيئات البناء، لذلك **خذ نسخة احتياطية من بيانات الإصدار القديم قبل إزالة أي APK**.

## خطوات Cloudflare وLiveKit
اقرأ `voice-backend/DEPLOY_AR.md` بكل تفاصيل الإعداد؛ ملخصها:
1. أنشئ مشروع LiveKit Cloud جديدًا، واحصل على عنوان `wss://...livekit.cloud` ومفتاح API والسر؛ لا تشاركها داخل المحادثة.
2. أنشئ قاعدة D1 على Cloudflare باسم `ahlquran_voice`، وعدّل معرفها في `voice-backend/wrangler.toml`، ثم نفذ `schema.sql` على قاعدة الإنتاج.
3. اضبط أسرار Cloudflare: `LIVEKIT_URL`, `LIVEKIT_API_KEY`, `LIVEKIT_API_SECRET`, `BOOTSTRAP_SECRET`.
4. انشر Worker للحصول على `https://ahlquran-voice.YOUR-SUBDOMAIN.workers.dev`، وأنشئ المدير مرة واحدة باستخدام السر من سطر الأوامر كما في الدليل.
5. انسخ عنوان Worker **العام فقط** داخل `voice-config.js`، وارفع التحديث إلى GitHub ثم ابنِ APK جديدًا.
6. سجّل دخول المدير السحابي في «الغرف الصوتية» وأنشئ حساب المعلم والطلاب؛ ادخل على هاتف المعلم بنفس بيانات حسابه السحابي، وأنشئ غرفة وحدد الطلاب؛ يدخل الطلاب بحساباتهم من هواتفهم، ويستمعون قبل أن يسمح لهم المعلم بالتسميع.

## الأمان والحدود
جلسات سحابية مؤقتة ومصادقة على الخادم؛ توكنات LiveKit قصيرة العمر ومحددة لغرفة بعينها وبمصدر صوت الميكروفون فقط. الطالب الذي ليس في قائمة المدعوين لا يحصل على توكن دخول. المدرس هو صاحب صلاحية إنشاء/إنهاء الغرفة وتحديد المتحدثين. قد يتطلب تغيير إذن التسميع مغادرة الطالب وإعادة انضمامه إذا تعذّر تحديث LiveKit للمشارك الحالي. يدعم التطبيق طلب إذن الميكروفون في Android فقط ولا يحتوي على إذن الكاميرا. تكلفة خدمة LiveKit وخططها تعتمد على الاستخدام؛ لا تفترض أنها مجانية بلا حدود.

## اختبارات منفذة
`node --check app/src/main/assets/app.js && node --check app/src/main/assets/voice.js && node --check voice-backend/src/index.js && (cd voice-backend && node test-api.mjs)`
نجحت اختبارات الصحة/CORS ورفض مسارات API بدون تسجيل، وفحص JavaScript. لا يتضمن هذا إثبات نجاح تجميع APK أو التشغيل الصوتي على الشبكة الفعلية؛ تجميع APK يتم عبر GitHub Actions.
